# FlacToAiff — Implementation Work Plan (2026-07-09)

Derived from `docs/CODE_REVIEW-2026-07-09.md`. Four sequential steps, ordered by risk-reduction and dependency. Every step ends with `./build.sh && ./test.sh` green so the app is always shippable.

Facts verified on this machine (macOS Apple Silicon, CLT-only, Swift 5.10) while drafting this plan:

- `afinfo -x` emits namespaced XML (`xmlns="http://apple.com/core_audio/audio_info"`); the FLAC source depth is in `<source_info><bit_depth>24</bit_depth>`, while the per-track `<bit_depth units="bits">` is `0` for FLAC — do not use the track-level node.
- `afconvert -f AIFF -d BEI32 in.flac out.aiff` works and yields `32-bit big-endian signed integer` per `afinfo`.
- The current sources compile unmodified with `swiftc -target arm64-apple-macos12.0` (CLT SDK 14.4) and produce `minos 12.0`. C1's fix is therefore the `-target` flag, not a plist downgrade.

## Step 1 — Conversion-core correctness: make "Quality preserved" true

**Findings:** H1 (bit-depth clamp), H2 (lossy failure default), H3 (unanchored regex / filename-echo false match), M2 (pipe deadlock), L2 (partial-file corpse), plus the L1 test-coverage gaps that exercise them.
**Files:** `Sources/Converter.swift`, `test.sh`. No GUI or build changes — the CLI seam (`--convert`) tests everything here.

### 1a. Replace regex detection with `afinfo -x` XML (H3, H2)

Replace `detectBitDepth` (`Converter.swift:25-36`) entirely. Return `Int?` so the *caller* picks the fail-safe, and parse the XML deterministically:

```swift
/// Detect the source PCM bit depth of a FLAC via `afinfo -x` (XML).
/// Returns nil when detection is impossible; callers must fail toward lossless.
static func detectBitDepth(_ url: URL) -> Int? {
    guard let xml = runCapture(afinfo, ["-x", url.path]),
          let doc = try? XMLDocument(xmlString: xml) else { return nil }
    // Doc uses a default namespace — match by local-name() instead of registering it.
    // FLAC's real depth is <source_info><bit_depth>; the track-level <bit_depth> is 0.
    let nodes = (try? doc.nodes(forXPath:
        "//*[local-name()='source_info']/*[local-name()='bit_depth']")) ?? []
    guard let text = nodes.first?.stringValue,
          let depth = Int(text.trimmingCharacters(in: .whitespaces)),
          (1...32).contains(depth) else { return nil }
    return depth
}
```

This retires H3 by construction: no free-text scan, so a file named `16-bit dreams.flac` can never poison detection via afinfo's path-echo line, and there is no `filter(\.isNumber)`-over-the-whole-match bug.

### 1b. Correct the depth → AIFF format mapping (H1, H2)

Replace `Converter.swift:59` (`detectBitDepth(flacURL) == 24 ? 24 : 16`):

Update the doc comment at `Converter.swift:53` and README.md:7 wording ("16-, 24- or 32-bit is matched, rounding up, never down").

### 1c. Fix the latent pipe deadlocks (M2)

- `Converter.swift:77`: `p.standardOutput = Pipe()` → `p.standardOutput = FileHandle.nullDevice`
- `Converter.swift:91`: `p.standardError = Pipe()` → `p.standardError = FileHandle.nullDevice`

Rationale: an attached-but-never-read `Pipe` blocks the child once it writes ~64 KB (afinfo's `-x` output plus warnings can approach this on large/odd files), which hangs `readDataToEndOfFile` forever. `nullDevice` discards without buffering. The existing stderr-before-`waitUntilExit` order in `run()` stays as-is (it's correct).

## Step 2 — Concurrency and "Never overwrites" integrity

**Findings:** C2 (second drop mid-batch → overwrite race + two concurrent loops), the lost-results/last-writer-wins bug (`main.swift:158-162`), M1 (no live per-file status).
**Files:** `Sources/main.swift`, `Sources/Converter.swift` (`uniqueOutputURL`), `test.sh`.

### 2a. Reject drops while a batch is running (C2, part 1)

`handleDrop` (`main.swift:116`) becomes `-> Bool` and the `onDrop` closure (`main.swift:102-105`) returns its result so the system shows the "not accepted" cursor:


```swift

    guard !working else { return false }   // C2: one batch at a time
    results = []
    produced = []
    working = true
    ...
    return true

```

This alone guarantees a single conversion loop, which also kills the last-writer-wins results clobbering (only one `group.notify` block can be in flight).

### 2b. Atomically reserve output names with O_EXCL (C2, part 2)

Even with 2a, the CLI mode (and any future parallelism) can race two processes on the same name — and `afconvert` overwrites. Replace the check-then-use loop in `uniqueOutputURL` (`Converter.swift:40-50`) with an atomic claim:

```swift
/// Atomically claim `url` (O_CREAT|O_EXCL). True = we own this name now.
private static func reserve(_ url: URL) -> Bool {
    let fd = open(url.path, O_CREAT | O_EXCL | O_WRONLY, 0o644)
    guard fd >= 0 else { return false }
    close(fd)
    return true
}

/// A `.aiff` URL in `destDir` that is *reserved* for the caller (zero-byte file created).
static func uniqueOutputURL(for flacURL: URL, in destDir: URL) -> URL {
    let base = flacURL.deletingPathExtension().lastPathComponent
    var candidate = destDir.appendingPathComponent(base + ".aiff")
    var n = 2
    while !reserve(candidate) {
        candidate = destDir.appendingPathComponent("\(base) \(n).aiff")
        n += 1
    }
    return candidate
}
```

Notes:
- `afconvert` overwriting the zero-byte reservation is fine — the name is ours.
- The Step 1d failure-path unlink now also releases the reservation, so a failed convert doesn't permanently burn `song.aiff`.
- `convert` already calls `createDirectory` (`Converter.swift:57`) before `uniqueOutputURL`, so `O_CREAT` can't fail on a missing directory. Keep that order.
- Existing test 4 (auto-rename) still passes unchanged: reservation subsumes the old `fileExists` check.

### 2c. Live per-file status (M1 + lost-results)

Rework the batch loop (`main.swift:142-163`) to publish per file instead of once at the end:

```swift
group.notify(queue: .global(qos: .userInitiated)) {
    for u in urls {
        if u.pathExtension.lowercased() != "flac" {
            DispatchQueue.main.async {
                results.append(FileStatus(name: u.lastPathComponent, ok: false,
                                          detail: "Skipped — not a .flac file"))
            }
            continue
        }
        do {
            let out = try Converter.convert(flacURL: u, destDir: dest)
            DispatchQueue.main.async {
                produced.append(out)
                results.append(FileStatus(name: u.lastPathComponent, ok: true,
                                          detail: "→ \(out.lastPathComponent)"))
            }
        } catch {
            DispatchQueue.main.async {
                results.append(FileStatus(name: u.lastPathComponent, ok: false,
                                          detail: "\(error)"))
            }
        }
    }
    DispatchQueue.main.async { working = false }
}
```

No new state or locking needed: all mutations of `results`/`produced` stay on the main queue; the loop remains serial on the background queue. The existing view already switches from the "Converting…" label to the list the moment `results` is non-empty (`main.swift:69`), so rows appear live; the Reveal/Clear row stays hidden until `working == false` (`main.swift:46`). A cancel button remains out of scope (afconvert is per-file and fast); note that in the design doc if desired.

## Step 3 — Build, packaging, and platform truth

**Findings:** C1 (minos 15.0 vs plist 12.0), M6 (unstable code identity → TCC re-prompts), M3 (`--convert` arity silently launches GUI), build.sh failure hardening.
**Files:** `build.sh`, `Sources/main.swift` (CLI block only), `test.sh`.

### 3a. Pin the deployment target and verify it in the build (C1)

`build.sh:11-14`:

```bash
    -target "$TARGET" \
```

Already verified: the current source compiles clean at 12.0 and emits `minos 12.0` — no SwiftUI API in use postdates macOS 12 (plain `VStack`/`ScrollView`/`onDrop`/`NSHostingView`). Make the plist claim self-enforcing so C1 can never regress silently — add after compilation:

```bash

[ "$MINOS" = "12.0" ] || { echo "FAIL: binary minos=$MINOS, plist claims 12.0"; exit 1; }
```

Caveat to document in README: "runs on macOS 12" is now *link-level* true; behavioral verification on a real macOS 12 machine remains untested (no such machine here). If access to macOS 12–14 is never expected, the alternative is raising `LSMinimumSystemVersion` — but since the code compiles at 12.0 for free, take the `-target` route.

### 3b. Stable ad-hoc identity, bound plist (M6)

Append to `build.sh` after the plist heredoc:

```bash
echo "Signing (ad-hoc, stable identifier)…"
codesign --force --sign - --identifier local.flactoaiff "$APP"
codesign --verify --strict "$APP"
```

Signing the *bundle* (not the bare binary) binds `Info.plist` into the code seal and replaces the linker-signed flags. Verify with `codesign -dv build/FlacToAiff.app` → expect `Identifier=local.flactoaiff` and `Info.plist entries=…` instead of `Info.plist=not bound`. Honest limitation to note in README: an ad-hoc signature still has no Team ID and no designated requirement chain, so TCC's Downloads grant survives *re-signing identical code* but not a rebuild that changes the binary; the full fix is a Developer ID certificate (out of scope). Also note: launching the binary from Terminal attributes the TCC prompt to Terminal — always test grants via Finder double-click of the `.app`.

### 3c. build.sh failure hardening
